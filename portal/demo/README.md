# Демо портала pharma_cert

Канон этого дерева — репозиторий [`SinopticsAI/pharma_ui`](https://github.com/SinopticsAI/pharma_ui).
Деплой на `https://pharma.sinoptics.ru` — [`infra/README.md`](../../infra/README.md).

Основной интерфейс — русскоязычный регуляторный кабинет. Единица работы в нём не «заявка со статусом», а **кейс продукта с порядком работ**: в каждую работу можно войти, увидеть статус, приложить документы по чеклисту, подтвердить исполнение и внести правки.

Кабинеты КНР и РФ для показа инвесторам сохранены на отдельных путях.

Это не продукт и не прототип продакшена. Целевая архитектура описана в
[`pharma_cert/portal/view/06-frontendnoe.md`](https://github.com/SinopticsVit/pharma_cert/blob/main/portal/view/06-frontendnoe.md).

**Дата среза данных:** 28 августа 2026 года.

## Запуск

```powershell
cd portal\demo
npm install
npm run demo
```

| Адрес | Что открывается |
| --- | --- |
| `http://localhost:4173/` | Кабинет pharma_cert, русский язык |
| `http://localhost:4173/cn/` | Кабинет производителя, основной язык 中文 |
| `http://localhost:4173/ru/` | Консоль оператора РФ |
| `http://localhost:4173/split/` | Лаунчер инвесторов и режим «рядом» |

Разработка кабинета: `npm run dev` (порт 5175). Контуры КНР/РФ — `npm run dev:cn` и `npm run dev:ru`.

Шрифт Inter подключается из пакета `@fontsource/inter`, без CDN.

## Порядок работ

Порядок строится от типа продукта, выбранного при вводе: лекарство, протез или оборудование. Общая часть — ввод карточки, её проверка и поиск в государственных реестрах. Дальше треки расходятся.

| Код | Работа | Комментарий |
| --- | --- | --- |
| 0.1 | Карточка продукта | Наименование, тип, страна, производитель, площадки |
| 0.2 | Проверка карточки | Формальные правила полноты, пограничная квалификация эскалируется юристу |
| 0.2.1 | Проверка в реестрах | Виджет реестра медицинских изделий и ГРЛС. Если запись найдена, новая подача не требуется |
| 0.3 | Досье производителя | Инструкция, техописание, модели, материалы, риски, ISO 13485, макеты этикеток |
| 0.3.1 | Класс риска, вид НКМИ, трек СИ | Для лекарства вместо этого — тип препарата и стратегия GMP |
| 0.4 | Перевод на русский | С обязательной медицинской редактурой |
| 0.5 | Легализация и мандат | Отдельные слоты по п. 87: доверенность, полномочия подписанта, 营业执照, площадка, товарный знак, ISO |
| 0.6 | Подбор лаборатории | Область аккредитации проверяется в реестре аккредитованных лиц |
| 0.7 | Договоры лаборатории и метрологии | Для оборудования — параллельно |
| 1 | Уведомление о ввозе образцов | ЕПГУ 610095, до отгрузки, пошлины нет. Не форма 630782 и не право продавать |
| 2 | Таможенное оформление образцов | Цель ввоза — государственная регистрация, не коммерция |
| 3, 3.1, 3.2 | Испытания, утверждение типа СИ, инспекция | Кабинет 630782 здесь ещё не нужен: прикладывать нечего |
| 4 | Заявление на регистрацию | ЕПГУ 630782. Следующий аппарат — новое заявление, союзный трек — услуга 613264 |
| 5 | Статусы, запросы и досылки | Кабинет заявителя Росздравнадзора |
| 6, 6.1 | После регистрации | Коммерческий ввоз и, при необходимости, маркировка |

Заблокированная работа не открывается, пока не закрыты её предшественники, и показывает, чего именно ждёт.

## Сценарий показа

1. Кейс CERT-2026-0094 «Тонометр автоматический BP-90A»: порядок работ, закрытая подготовка и открытая работа 1.
2. Работа 1 «Уведомление о ввозе образцов»: ссылка на услугу 610095, пометки «когда», «пошлина» и чем услуга не является.
3. Работа 0.5: чеклист легализации по пунктам правил, нотариус и апостиль у каждого документа.
4. Загрузка документа в слот и подтверждение работы исполнителем: обе операции попадают в журнал.
5. Работа 0.2.1 на другом кейсе: если запись в реестре найдена, кейс переходит в сопровождение и дальнейшие работы помечаются как не требующиеся.

Состояние кабинета хранится в браузере и переживает перезагрузку. Сброс — на странице «Настройки».

Для инвесторов остаются кабинеты КНР и РФ: кнопка «Показать рядом» на лаунчере открывает оба в одном окне.

## Как устроено

```text
apps/web-portal  регуляторный кабинет pharma_cert: кейсы и порядок работ
apps/web-cn      кабинет производителя, ZH основной
apps/web-ru      консоль оператора РФ, только RU
packages/ui      токены презентации, компоненты кабинетов КНР/РФ
packages/i18n    каталог ZH/EN/RU и форматтеры
packages/domain  типы кейса, документа, строки ledger, мандата
packages/mock    сид-данные, состояние в localStorage, имитация API
launcher         страница показа инвесторам и режим «рядом»
scripts          проверка стоп-листа и демо-сервер
```

Стек: Vite, React, TypeScript strict, TanStack Router и TanStack Query, CSS Modules поверх токенов из [`ppt/DESIGN-CONCEPT.md`](../../ppt/DESIGN-CONCEPT.md).

Состояние демо лежит в `localStorage` под ключом `pharma-portal-demo-state-v1`. Обе сборки раздаются с одного origin, поэтому событие `storage` синхронизирует вкладки: изменение в консоли оператора инвалидирует кеш запросов в кабинете производителя, и тот перерисовывается сам.

Цифры взяты из research-пакета: пошлины по классам 72 / 104 / 136 / 184 тыс. руб. плюс 11 тыс. за выдачу РУ, испытания во ВНИИИМТ около 478 тыс. руб., нормативные отрезки 5 / 2 / 31 / 50 рабочих дней. Каждая сумма и срок сопровождаются пометкой «ориентир · 28.08.2026 · не оферта».

## Что демо соблюдает

- Кабинет производителя не содержит маршрутов подачи и реквизитов криптоконтура — не скрывает их, а не содержит. Реквизиты ЕСИА, УКЭП и МЧД вынесены в модуль, который подгружается только консолью РФ, и в JavaScript-бандл кабинета КНР не попадают.
- Статус вносит человек и прикладывает артефакт. Парсинга государственных форм нет.
- Строка комиссии и строка третьей стороны — разные типы записи. Свернуть их в одну сумму нельзя.
- Статусы кодируются формой и подписью. Светофорных индикаторов нет; дедлайн и риск — единственное применение янтарного цвета.
- Данные условные, поэтому в интерфейсе нет ни печатей, ни гербов, ни выданных регистрационных удостоверений, ни прогресса «87 % до РУ».
- `npm run check:copy` роняет сборку на формулировках из стоп-листа [`portal/view/05-marketingovoe.md`](../view/05-marketingovoe.md) §7.

## Отступления от целевой архитектуры

| Отступление | Почему | Как будет в продукте |
| --- | --- | --- |
| Один origin, пути `/cn` и `/ru` | Иначе не работает синхронизация вкладок, а она и есть главный кадр показа | Разные origin, разные OAuth-клиенты и наборы scopes |
| npm workspaces вместо pnpm | pnpm недоступен на машине сборки без прав администратора | pnpm workspaces и Turborepo, когда появится третье приложение |
| `packages/mock` вместо `packages/api-client` | Демо работает без бэкенда | REST и OpenAPI, клиент генерируется из спецификации |
| Консоль РФ пишет строки в коде, без каталога | Приложение одноязычное по концепции | Так же: каталог нужен только кабинету производителя |
| Собственные компоненты вместо React Aria | Меньше зависимостей для офлайн-стенда | React Aria как компонентная база `packages/ui` |
| Публичного сайта и калькулятора нет | Вне объёма первой версии демо | Отдельное приложение `web-public` |

## Проверка перед показом

1. `npm run demo` — стоп-лист, сборка и сервер должны пройти без ошибок.
2. Открыть лаунчер, нажать «Показать рядом».
3. В консоли РФ внести статус и убедиться, что кабинет слева обновился без перезагрузки.
4. Переключить язык кабинета на 中文 и EN, проверить, что заголовки и таблицы не обрезаны.
5. Нажать «Сбросить демо» перед следующей встречей.
